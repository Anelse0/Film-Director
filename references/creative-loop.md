# 创作回路与诊断后重写

流水线是逐级交付的，但创作不是。本文件规定三件事：发现怎样回流、批评怎样定位、重写怎样不伤原稿。适用于 S3a–S5；表演优先路由与生产链路（S5b–S7 的素材绑定、保真、预检）不受影响。

## 一、允许的回流

| 发现发生在 | 可以回到 | 做法 | 不能做 |
|---|---|---|---|
| 概念阶段试写片段 | 概念（创作判断、候选） | 片段里人物说话的方式、注意的东西、场景里让人看下去的点，写回候选的"独特之处"或改主控句 | 把片段当剧本交付 |
| 剧本页写不顺 | 故事层（场景清单、人物） | 台词总是在解释 → 场景的实际问题不对；人物没法说这句 → 人物"注意什么 / 对谁改说法"没定 | 在台词层硬改到能说为止 |
| 表演外化时发现 | 人物设计（声音表、绝不会做） | 表演条目揭示了人物控制情绪的方式，写回人物栏，供后续场景使用 | 改已确认的台词或事件 |
| 分镜时发现 | 剧本页（空间、物件） | 可见性要求改动作位置或物件；不改事件与台词 | 为镜头好看改人物选择 |
| 成片反馈 | S5 / S6（按 `stage-7` §7.2） | 定位到镜头卡 | 借修成片重写故事 |

所有回流都不能越过用户已锁定的内容（`00_brief.md` 创作判断的"锁定"行、已确认的停靠产物、用户给定的角色 / 场景 / 台词 / 视觉资源）。回流改动了上游产物时，在交付里说明"这一处因为下游发现改了"。

## 二、收到批评后：先诊断，再决定层级

用户说"太假 / 太平 / 不喜欢 / 没意思"时，先定位，不先改：

| 症状 | 最可能的层 | 检查 |
|---|---|---|
| 逻辑通但没意思 | 观众侧：期待没有被建立或改变 | 观众此刻知道什么、期待什么、哪个证据改变判断（`character-scene-development.md` §一） |
| 反转惊人但人物不可信 | 人物侧：回应方式没有依据 | 他认为发生了什么、为什么选择这种回应；缺材料按 `research-to-craft.md` 补 |
| 台词像同一个人写的 | 人物声音 | 注意什么 / 对谁改说法 / 被误解时怎样保护自己 / 听到哪部分不回应 |
| 每句都对，连起来没推动 | 因果链 | `causal-chain.md` 三测 |
| 场面没有画面 | 主控画面 / 空间 | 物件 + 动作 + 光有没有；空间是不是类别名 |
| 全片都在对抗，累 | 叙事方式单一 | 是否有一场可以用靠近、揭示、积累或余韵 |
| 30 秒塞不下 | 事件承载 | 保留关键事件与表演高光，重排同步 / 先后（`stage-3c` §3c.7） |

诊断写一行："问题在 __ 层，因为 __。"然后只改那一层及其下游。

## 三、重写的纪律

1. **保留上一版。** 对话里保留上一版原文或明确引用；落盘时写 `scene-XX.v2.md` 或在文件头记录版本，不覆盖。
2. **说明改了什么、解决什么。** 每次重写交付前两行：改动清单（哪几句 / 哪几个动作）+ 对应解决的诊断。
3. **检查有没有失去原稿有效的细节。** 逐条对照上一版：被删的句子 / 动作 / 物件里，哪些承载了识别性、回应关系、控制过程、母题？失去的写明理由；说不出理由的恢复。
4. **不把每次重写变成另一个故事。** 事件、人物选择、主控画面不因局部批评而换掉；要换属于回到 S3a / S3b，需要用户决定。
5. **定点重写。** 用户批评具体某句时，改那句和它直接牵动的上下句，不顺手重写整场。

## 四、示例：为什么"我今天回来了"不能换成漂亮话

示例 04〈行李箱〉的 30 秒里，她指认他反复缺席，他反击"你自己哪天九点前进过这个门"，三秒沉默后她说"我今天回来了"。这句的力量来自它是对上一句指责的回应，并且说出了两人的共同处境：她今天回来了，他今天要走。

假设收到批评"结尾太淡"。错误的重写：把它换成一段总结感情的漂亮话（"我们都在用离开惩罚对方"）。诊断：问题不在这句，它通过遮住测试（遮住上一句，能猜到他刚指责她不回家）和删除测试（删掉它，结尾只剩离开，失去了回应关系）。如果"太淡"成立，更可能在观众侧——观众是否在此前已经知道她平时几点回家，才能在这句听出代价。定点修法是在前面补一个证据（例如她进门时鞋柜里只有他的鞋），而不是换掉这句。

## 五、场景写作的可选步骤

John August 的场景写法（2007，`screenwriting-traditions.md` §五）可以作为回路里的工具，不必原样走完：这场戏必须发生什么 / 删掉会怎样 / 谁该在场 / 地点还能是哪里 / 有没有意外的可能 / 值得多长 / 三种不同的进入方式 / 在脑子里排演 / 先写潦草版再写正稿。其中"三种进入方式"与"潦草版"最常用：进入方式决定观众带着什么期待进场；潦草版让人物先说话，再决定保留什么。

## 六、与其他文件的关系

- `concept-generation.md` 第 5 步试写是回路的入口之一。
- `character-scene-development.md` 提供诊断用的人物侧 / 观众侧问题与人物声音问题。
- `causal-chain.md` 三测用于"每句都对但不推动"。
- `stage-7-qa-continuity.md` §7.2 处理成片反馈；本文件处理文本层的批评。
- `preference-ledger.md` 记录用户确认过的偏好，重写时先查是否已有明确偏好。
