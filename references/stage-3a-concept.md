# S3a 概念阶段

概念回答"这东西为什么值得拍、观众会怎样理解它"。产出：选定后的 `01_concept.md`（模板 `templates/concept.md`）。概念是一种成果类型，不是进入故事的审批关卡：用户带来成熟的想法或片段时，可以先试写或先发展故事，概念判断随后回写。候选怎么来见 `concept-generation.md`。

## 3a.0 素材驱动入口

很多项目不是从想法开始，是从一张脸、一个房间、一段音色开始。这时候不要先想故事，先审素材。对每个素材问三句，答案写成可观察的句子：

| 素材 | 三问 |
|---|---|
| 角色图 | 这张脸刚做完什么？它绝不会做什么？它在等谁？ |
| 场景图 | 这个房间在等谁进来？最不该出现在这里的东西是什么？主光源在哪、几点钟？ |
| 音色 | 这个声音会说什么样的谎？它说不出口的一个词是什么？ |
| 动作参考视频 | 这个动作如果发生在错误的地点会怎样？ |

从答案里挑两条互相牵扯的，拼成处境（"这张脸在等人，但这个房间在等别人"）。素材驱动的候选天然带着可拍性，因为主控画面已经在素材里。

## 3a.1 候选常见的弱点

写完候选后逐条查（这是审阅，不是每个候选必须填满的表格）：

1. **主题词伪装**："关于失去"不是候选，候选要有人、他在做的事、什么拦着他或什么在向他靠近。
2. **没有代价或变化**：阻力要让人物付出看得见的代价，靠近型的故事要让关系或理解看得见地变化；"他想留下，但是下雨了"只是天气。
3. **落差只在台词里**：期待与结果的落差要发生在行为、事件或观众理解上，台词里的机灵话不算。
4. **只换了设定**：候选之间只有职业、地点、道具不同，人物怎样理解处境、关系、事件后果与观众继续看的理由都一样。合并，或说清差异。

## 3a.2 主控句（可选工具）

一句 ≤ 20 字、尽量不用形容词、可以裁决决定的话，例如"每个人都在等对方先开口"（→ 台词少；镜头等人；无音乐）。有它时后续分镜可以拿它裁决；写不出时先写暂定版或留空，不作为进故事的门槛。主控句可以在试写或故事之后修订。

## 3a.3 观众记住什么（可选自检）

三问帮助发现候选是否只是漂亮设定：观众三天后还记得的一个画面是什么？哪一秒观众对人物的判断变了？角色做了什么可见的选择？答不出不等于候选不成立——有的故事靠关系积累或余韵成立（`character-scene-development.md` §二）；答得出的写进候选。

## 3a.5 概念模式的交付（在对话里，不是文件）

交付格式见 `concept-generation.md` §交付。规则：

- 候选数量由任务决定（用户已锁定方向可以只发展一个），不固定。
- 有多个候选时，写清它们在人物怎样理解处境、人物之间的关系、什么事发生及后果、观众为什么继续看这几个维度上哪里不同；只换职业、地点、道具不算。
- "这 N 秒拍什么"只写一行画面与变化，防止在概念阶段偷偷做分镜。
- 不写角色小传、不写镜头。关键场景试写是例外：用于发现人物实际会怎样回应、原来的故事假设是否成立，不当剧本交付。
- **选定前不落盘。** 用户选定后写 `01_concept.md`：选定候选全文 + 被否候选各一行与否决理由 + 研究记录 + 创作判断。
- 可以推荐；不预选。

## 3a.6 概念卡

模板：`templates/concept.md`。字段：创作判断（四行，可暂定）· 默认地图 · 候选（选定的全文，被否的各一行）· 研究记录（缺口 / 材料与来源 / 具体发现 / 可信范围 / 影响哪项决定；无外部事实依赖时可空）· 基调。主控句、三问、默认画面地图的理由、默认透镜倾向都是可选字段，写了有用，空着不算缺。

选定后跑 `python3 scripts/validate_concept.py 01_concept.md`；ERROR 修，WARN 逐条写理由或补齐。脚本只查格式与完整性：空候选、示例照搬是错误；常见标题本身不是抄袭证据。
