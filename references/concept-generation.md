# 概念生成协议

`stage-3a-concept.md` 规定概念长什么样；本文件规定概念**怎么来**。目标不是产出更多"看起来有创意"的概念，而是让用户更常选到值得继续发展的故事：选题可辨识、人物可信、场景有吸引力，并且在后续剧本、表演、Prompt 里仍保有最初吸引人的东西。

## 概念阶段契约（先读）

概念是用户还没做的决定。决策阶段与生产阶段的规则相反：

| | 生产阶段（S3b 之后） | 概念阶段（S3a） |
|---|---|---|
| 落盘 | 每阶段产物写文件 | **选定前不写任何文件**。候选只在对话里。用户选定后才写 `01_concept.md`（模板 `templates/concept.md`） |
| 选择 | 模型按规则决定 | **模型不预选**。可以推荐并说理由，但"最佳 / 已选 / top"在用户选之前不出现 |
| 示例 | 母版可实例化 | **示例禁止复用**。工作示例在 `examples/concept-worked-examples.md`，概念模式默认不读 |
| 过程 | 只交结果 | **来路可见**。交付时用两行说明候选从哪个入口来、研究补了哪个缺口 |
| 停靠 | S5 后停 | 需要用户做方向决定时停（例如处境或人物入口有多个方向且会导致不同的候选）；不固定停几次 |

用户说"存一下候选"时可写 `01_concept-candidates.md`，这是唯一例外。

## 为什么需要协议

模型在一个题目下会取最可能的答案。用户否决一个，模型从同一个中心再取一个。否决只改变输出，不改变分布。改变分布只能改输入：知道默认答案在哪、注入真实细节、从人物与观众理解出发而不是从题材出发。

AI 辅助短篇写作的研究发现，个体作品评价可以改善，同时不同作品之间可能更相似（Doshi & Hauser 2024）。所以多样性要单独检查，不能靠"多写几个"自动获得；这项研究也不能证明本协议有效，仍须对照盲测（`tests/creative-eval.md`）。

## 第 0 步 创作判断（简短，不要求用户填表）

在题材、情绪之外，先写四行判断。写不准可以先写暂定，允许通过试写逐渐发现作品真正关心的问题：

- 观众最初会怎样理解这件事？
- 我们希望他们最后怎样理解人物？
- 本作最值得保留的独特之处是什么？
- 哪些是用户锁定的，哪些允许探索？

不强迫概念阶段就写出正确的主题金句。Kaufman 在 BAFTA 讲座里描述自己"从不知道开始"、带着兴趣去探索而不预设去向 `[第三方转述]`；本 Skill 据此保留发现空间，但仍要求结构判断与修订，这是本 Skill 的设计选择 `[推论]`，不是 Kaufman 的主张。

## 第 1 步 默认地图（替代旧"禁用表"）

写出这个题目下观众和模型最先想到的几个答案，具体到能一眼认出（"绝症"、"车站告别"、"翻旧照片"）。这不是禁令：候选可以落在地图上，熟悉题材也能写出好故事；落在地图上的候选写出它在**人物怎样理解处境、关系、事件后果或观众理解**上与默认答案的具体差异。写不出差异时，或者合并，或者说明它为什么仍值得发展，不以猎奇和反转代替原创性。

集中研究一个题材（例如分手）是合法的；不合法的是候选之间只换了地点。

## 第 2 步 入口（按任务选，可组合，不要求全部）

| 入口 | 何时用 | 做法 |
|---|---|---|
| 用户已有想法 | 用户带来人物、事件或一句话 | 发展它，不替换它。锁定部分不动，探索部分写明 |
| 人物入口 | 用户给了职业、身份或关系 | 先问这个人一天怎么过、注意什么、忽略什么、对谁改说法；缺口按 `research-to-craft.md` 补 |
| 处境入口 | 只有情绪与关系（"男女爱情，悲"） | 把情绪展开成多种处境（分离 / 失去 / 不能 / 时间 / 隐瞒 / 照护 / 制度 / 错认 等轴只是提示）；方向有多个且会长出不同故事时停一次让用户选 |
| 素材入口 | 用户有角色图、场景图、音色、动作视频 | `stage-3a-concept.md` §3a.0 三问 |
| 规则入口 | 情感内核放进有真实规则的领域 | 规则本身是阻力或靠近的方式；规则必须核实（§第 3 步） |
| 物件履历入口 | 想从日常物件出发 | 写一件物件三年的使用痕迹：谁买的、谁改过设置、哪里磨损、最后一次被用来干什么 |
| 试写入口 | 概念模糊但有语感，或用户给了一句对白、一个关系、一个片段 | 直接试写最有生命力的场景片段，看人物在里面怎么说话、注意什么、原来的假设是否成立；片段只用于发现，不当剧本交付 |

处境入口的停靠问法：一行格式约束 + 编号多选（附一行"会长出什么样的故事"）+ "你定"。有 AskUserQuestion 工具时用它。

## 第 3 步 研究服务缺口

按 `research-to-craft.md`：先认缺口（不懂人物 / 行为不可信 / 台词悬浮 / 依赖制度），再查；关键事实读正文，区分真实材料、创作推演与虚构设定；每条材料只记具体发现、可信范围、影响哪项决定。没有次数预算，也没有"摘要矛盾取新"的规则。候选的转折依赖某条规则时，该规则必须有记录；查不到就标"虚构，片中需自洽"，不得冒充真实。

禁止搜"创意 / 点子 / story ideas / 短片 idea / 剧本灵感 / 感人"——这些只会得到别人的故事。

## 第 4 步 候选发展

**候选数量由任务决定**：用户已锁定方向时可以只发展一个；用户在选方向时给几个真正不同的即可，多不等于好。

### 差异发生在哪里（比较维度，不是每个候选必填的表格）

需要多个候选时，先检验它们的差异发生在哪里。四个维度用于比较候选，不要求每个候选把四格填满：

| 维度 | 问什么 | 只换设定的假差异 |
|---|---|---|
| 人物怎样理解处境 | 这个人认为发生了什么、他把它当成什么问题 | 职业换了，理解处境的方式一样 |
| 人物之间有什么具体关系 | 谁欠谁、谁瞒谁、谁在照顾谁、谁说了算 | 地点换了，关系仍是"疏远的两人" |
| 什么事发生，带来什么后果 | 事件之后哪件事变得可能或不再可能 | 道具换了，事件仍是"一次告别" |
| 观众为什么愿意继续看 | 悬念、关系、观察、韵律、陪伴中的哪一种在起作用 | 三个候选都靠最后反转 |

熟悉题材可以写出好故事：差异在人物与事件上成立，题材是否常见不是问题。不以猎奇、反转或极端设定代替原创性；一个安静的候选如果人物理解处境的方式独特，比三个奇观候选更值得发展。

### 每个候选写什么

行是提示，写不出的行留空比编造好：

```
候选 〈短标题〉
一句话：谁 · 处境 · 他要什么 · 什么拦着或什么在靠近（不要求"但是"句式）
人物：他认为发生了什么 / 为什么选择这种回应
关系：两人（或几人）之间此刻的具体关系
观众：最初怎样理解 → 看见哪个证据后改变对人物的判断（或：靠什么持续吸引）
主控画面：观众会记住的一个画面（有物件、动作、光时写具体，没有不硬配）
这 {目标格式} 拍什么：一行，写画面与变化，不写镜头
独特之处：最值得保留的一点
依赖的事实与可信范围：一行（或"无外部事实依赖"）
风险：模型执行上最难的点
与其他候选的差异：人物怎样理解处境 / 关系 / 事件后果 / 观众为什么继续看——哪几项不同（多候选时写）
```

三个故事分别发生在医院、机场、婚礼，不代表它们真的不同；三个人物分别是护士、司机、教师，也不代表。

候选可以依赖冲突升级，也可以依赖欲望靠近、悬念揭示、关系积累或观察与余韵（`character-scene-development.md` §二）；不要求每个候选都有敌人、秘密或正负翻转。

因果自检（`causal-chain.md`）：遮住阻力或靠近的那一步，主控画面还成立吗？成立说明画面只是插图，不是后果。

## 第 5 步 关键场景先行（可选，可以早于候选）

用户给一句对白、一个关系或一个片段时，或者某个候选让人犹豫时，可以先试写最有生命力的部分：两个人物、一个具体空间、一件正在做的事，长度以看清人物怎样回应为准。试写不是给概念卡配插图，而是发现：

- 这个人实际会怎样回应？和候选里写的一样吗？不一样时，通常是试写对。
- 原来的故事假设还成立吗？（"她会一直隐瞒"在片段里可能三句就藏不住）
- 人物声音是否已经不同，场景里是否有让人看下去的东西。
- 最初吸引人的点在片段里还在吗？

片段里的发现写回候选或创作判断（`creative-loop.md` §一），不能越过用户锁定的内容。片段不落盘、不当剧本交付；用户喜欢它时，它进入故事阶段继续发展，而不是被概念卡"批准"。

Dee Rees 描述过从感兴趣的场景、句子和片段开始再组织结构的过程，Tony Gilroy 从一段律师处境的试写对话发展出项目 `[第三方转述]`（`screenwriting-traditions.md` §五）。本 Skill 据此开放"关键场景 → 人物发现 → 故事整理"的入口，同时保留概念判断作为核对工具；这是设计选择 `[推论]`。

## 交付（在对话里）

```
来路：入口 __；研究补了 __（一行）
默认地图：__（用到的候选标注差异）
候选 …（按第 4 步格式，写有内容的行）
推荐：〈__〉，因为 __。不推荐 〈__〉 因为 __。
（可选）关键场景试写：〈__〉，以及试写发现了什么
问题：选哪个？／按推荐继续？／要不要先试写一段？
```

## 常见失败

| 现象 | 处理 |
|---|---|
| 候选只是主题词（"关于失去"） | 回第 4 步：要有人、要做的事、什么拦着或什么靠近 |
| 候选之间只换了职业、地点、道具 | 用四个比较维度写差异；写不出就合并，或说明为什么仍值得并列 |
| 研究写成百科，没有一条指向决定 | 只保留影响决定的发现 |
| 真实人物的故事改名搬用 | 只借职业细节、空间、规则、表达方式 |
| 概念阶段偷偷分镜 | "这 N 秒拍什么"只写画面与变化 |
| 覆盖了用户已锁定的人物或事件 | 回第 0 步"锁定与探索" |
| 全部候选都在同一种叙事方式里（全是对抗） | 考虑一次欲望靠近、揭示或余韵能否成立 |
| 候选靠猎奇设定或最后反转撑着，人物怎样理解处境说不清 | 回比较维度：换掉设定后还剩什么；剩下的才是候选 |
| 试写片段比候选好看，但被当成概念的插图丢掉 | 片段里的回应方式与假设变化写回候选；片段可以直接进入故事阶段 |

## 交付前自检（`scripts/validate_concept.py` 只查其中可机械核对的格式项）

- [ ] 创作判断四行写了（可暂定）
- [ ] 默认地图写了；落在地图上的候选标了差异
- [ ] 每个候选有：一句话 / 人物 / 观众 / 主控画面 / 独特之处 / 依赖的事实
- [ ] 多候选时每个都有"与其他候选的差异"，差异不只是职业、地点、道具
- [ ] 研究记录每行有具体发现、可信范围、影响哪项决定、可回访的来源或"未核实 + 后果"
- [ ] 候选标题、查询没有一个来自示例
- [ ] 消息里没有"最佳 / 已选 / top"；有推荐、理由和一个问题
- [ ] 没有创建任何文件

选定落盘后：`python3 scripts/validate_concept.py 01_concept.md`。
