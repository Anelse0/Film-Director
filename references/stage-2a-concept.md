# S3a 概念阶段

在写任何场景之前先回答"这东西为什么值得拍"。产出：`02_script/concept.md`。**没有概念卡，不进 S3b。**

## 3a.0 素材驱动入口

很多项目不是从想法开始，是从一张脸、一个房间、一段音色开始。这时候不要先想故事，先审素材。对每个素材问三句，答案写成可观察的句子：

| 素材 | 三问 |
|---|---|
| 角色图 | 这张脸刚做完什么？它绝不会做什么？它在等谁？ |
| 场景图 | 这个房间在等谁进来？最不该出现在这里的东西是什么？主光源在哪、几点钟？ |
| 音色 | 这个声音会说什么样的谎？它说不出口的一个词是什么？ |
| 动作参考视频 | 这个动作如果发生在错误的地点会怎样？ |

从答案里挑两条互相冲突的，拼成前提（"这张脸在等人，但这个房间在等别人"）。素材驱动的前提天然带着可拍性，因为主控画面已经在素材里。

## 3a.0b 前提的三种失败

写完三候选后逐条查：

1. **主题词伪装**："关于失去"不是前提，前提要有人、要做的事和一个"但是"。
2. **无代价的但是**："他想留下，但是下雨了"——阻力必须让人物付出可见的代价，不然只是天气。
3. **反讽只在台词里**：落差必须发生在行为或事件上（先放手的是最想留的人），台词里的机灵话不算。

## 3a.1 三个候选前提

**候选必须来自 `concept-generation.md` 的五步协议**（禁用 → 种子 → 10 情境 → 评分 → 发展）。直接凭题目写三个候选的做法已废止。

### 3a.1 原规则

写 3 个互相不同的前提，每个 4 行。**目标格式已知时**（30 秒先导、竖版广告、三集短剧），先写一行格式约束（时长 / 单 clip 还是多 clip / 有无台词空间），候选必须在这个约束内成立：

```
前提：一句话，含一个"但是"（人物要 X，但是 Y）。
反讽：期待与结果的落差在哪（想留人的人先放手；最会说话的人说不出口）。
主控画面：如果全片只能留一个画面，是什么。必须是可拍的：物件 + 动作 + 光。
基调：两个词，一个是类型（正剧 / 喜剧 / 荒诞 / 惊悚 / 纪录），一个是温度（冷 / 温 / 灼）。
```

三个候选中至少一个是"你第一反应的反面"。选一个，写一行为什么，写一行为什么不选另外两个。

## 3a.2 主控句（L10）

一句 ≤ 20 字、不含形容词、可以裁决决定的话。测试：拿它去问三个具体问题（这场戏要不要台词？镜头动不动？用不用音乐？），每个问题它都能给出答案才算合格。

- 不合格："关于孤独。"
- 合格："每个人都在等对方先开口。"（→ 台词少；镜头等人；无音乐）

## 3a.3 观众记住什么

回答三问，答不出的回到 3a.1：

1. **画面**：观众三天后还记得的一个画面是什么？
2. **意外**：哪一秒观众会想"没想到"？
3. **选择**：角色做了什么可见的选择？（不是感受，是动作）

## 3a.4 反套路否决

下面这些是 AI 视频的默认产物。**出现即需要一行理由**，写不出就换：

| 套路 | 常见形态 |
|---|---|
| 悲伤脸缓推 | 近景 + 缓慢推近 + 泪 |
| 黄金时刻 | 逆光、暖金、镜头光晕 |
| 雨夜霓虹 | 湿地反光、蓝紫光 |
| 对视三十秒 | 两人面对面站着说话，没有物件、没有走位 |
| 背影看远方 | 人物背对镜头望向天际 |
| 慢动作情绪 | 用慢速代替表演 |
| 无来由手持 | 手持晃动但没有视点理由 |
| 万能 bgm | 用音乐补情绪 |
| 空镜开场 | 与人物无关的风景建立镜头 |
| 结尾微笑 | 一切用一个浅笑收束 |

否决不是禁止：〈钥匙〉可以用悲伤脸缓推，如果理由是"这是全片唯一一次镜头主动靠近母亲"。理由要能指回主控句。

## 3a.4b 概念模式的交付（在对话里，不是文件）

概念模式下用户要的是选择，不是文档。交付格式固定，每个候选 ≤ 6 行：

```
候选 1 〈短标题〉
前提：…但是…
反讽：
主控画面：
基调：类型 / 温度
这 {目标格式} 拍什么：一行，写画面与转折，不写镜头
风险：一行（模型执行上最难的点）

候选 2 …
候选 3（第一反应的反面）…

推荐：候选 _，因为 …。不推荐 _ 因为 …；_ 因为 …。
问题：选哪个？（或"按推荐继续？"）
```

模糊级需求先停一次让用户选处境（`concept-generation.md` 处境停靠），选定后再搜、再交付。交付消息开头两行（过程可见）：
```
处境（D0）：失智 · 照护 · 探视制度 · 倒计时 · 隐瞒病历 · 签证
领域（D1）：ICU 探视名单 / 知情同意须本人 / 签证到期日 / …（≥ 8 项，取 6 项展示）
```

规则：
- 三个候选的主控画面必须是三个不同的物件或空间，否则重写。
- "这 N 秒拍什么"只写一行，防止在概念阶段偷偷做分镜。
- 不写角色小传、不写台词、不写镜头。用户选定后再进 S3b。
- **选定前不落盘。** 用户选定后写 `02_script/concept.md`：选定概念全文 + 被否候选各一行与否决理由 + 检索记录。
- 三个候选各做过 D2，"风险"行写核实结论；不预选。

## 3a.5 概念卡

```
# Concept
候选 1 / 2 / 3（各 4 行）
选定：#_，因为：
不选：#_，因为：；#_，因为：
主控句：
三问：画面 / 意外 / 选择
反套路：本项目会用到的套路 + 理由（或"无"）
检索记录：粒度（D1 题材 / D2 规则）/ 查询 / 产出 / 来源（无 WebSearch 时写"未核实"）
基调：类型 / 温度
默认透镜倾向（可空；由各场景自行决定，此处只记录"整个项目不该用哪个透镜"）：
```
