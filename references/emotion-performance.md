# 情绪表演：调用、调节与保真

S4 的共用模块。用于原文调用、表演测试、强度/克制微调、情绪重组及完整影视流程中的角色表演。这里的尺度和估时是创作工具 `[推论]`，不是模型参数或效果保证。

## 入口与边界

- 只要表演测试：直接读本文件，检索库，再交付；不用先编故事、声音表、道具或人物小传。没有参考图不阻塞表演片段，也不虚构素材编号。
- 完整生产：S4 生成有序表演块；S5 解决可见性；S6 原样承接；S7 分层检查。已有台词、角色禁忌、镜头与用户确认的动作保持锁定。
- 用户需求和已确认内容优先于默认美学。真实技术限制与需求冲突时说明风险或选择；创作偏好不能伪装成技术限制。
- 原文调用不受本 Skill 的零副词、禁止照抄、通道配额、峰值静止等旧式限制。改编也不为满足规则而增加动作。

## 按需检索

`assets/emotion-library.json` 保存完整条目；`references/emotion-index.json` 是可更新的阅读索引，不是另一份原文。不要每次加载全库。

```bash
python3 scripts/emotion_library.py --list
python3 scripts/emotion_library.py --id 19 6
python3 scripts/emotion_library.py --query 害羞
python3 scripts/emotion_library.py --id 6 --raw
```

检索只是找候选，选择前读所选完整正文及关系提示。允许使用多条、单条或库外创作，不按中文情绪名称强制映射。库外写法说明“新编”，不要谎称原文；索引不是情绪本体，也不限制只有这些情绪能写。

## 模式

| 模式 | 处理 | 核对 |
|---|---|---|
| raw 原文直用 | 输出所选完整正文，说明放在正文外；不自动翻译、调强度、改结尾 | 逐字一致 |
| adapt 微调 | 单条基础上改幅度、速度、控制、角色适配或语言；记录实质改动 | 原条目 + 本次保留细节 + 有意调整 |
| blend 重组 | 从多条选择表现，组织时间与过渡；新增连接不冒充原句 | 每节拍关联条目；区分取材与新增 |

库外创作用 `free` 标记，不算第四种库内调用方式。中文译写属于 adapt；多条拼接属于 blend。用户同时要“原文不动”和改变内容时，分别交付原文与改编，或指出两者不能在同一正文同时成立。

## 控制维度（内部使用，用户不必填表）

- 情绪强度：可用相对描述或 1–5 记录内在情绪负荷；相同数字只用于同一测试条件下比较，不把它解释为客观量表。
- 克制：没有主动压制 / 部分控制 / 强控制，也可描述哪个通道被压住。强度高不代表动作大或说话多。
- 路径：持续、增强、控制松动、释放、转向另一情绪；按需求选择，不固定四拍或三段。
- 高光与末态：必须看见的变化，以及结束时还在做什么。高光完整不等于恢复平静。
- 时长、镜头、台词、角色与身体条件：沿用用户输入，只补本次必需的条件。

调节时回到可见证据：哪些肌肉/部位变化、幅度、发展快慢、停留、呼吸、同步关系、控制如何维持或失败。不要给每句统一加“轻微/剧烈”，也不要让所有通道随强度同比放大。“快要哭”是临界状态；“憋哭”包含控制行为；两者不是固定强度档位。

## 写作与时间编排

先确定所选条目的识别性细节、关系和末态，再决定本次保留与有意调整。写成有序表演块，不拆成相互失联的部位词表。

- 保留渐变、速度和幅度，如逐渐、缓慢、突然；它们描述执行，不是空泛情绪标签。“眼神动摇”可作引导，但需要视线或眼睑等具体证据。
- 同一部位连续变化可以构成完整表演；同一状态有意持续也可以成立。检查的是冗余和冲突，不是词频。
- 同时发生的眉眼、呼吸、肩部变化可以属于同一行为；不能按逗号逐项计成多个独立任务。动作也不能因为多个通道就被强制串行化。
- 先给目标高光的发展与可见持续留出时间，再安排必要铺垫；时间比例和节拍数量因动作而异，不预设 0–3/3–6/6–10。
- 时间不足：优先去掉无关事件或减少情绪节点；必要时说明时长取舍。不要通过删掉识别性细节来伪装为“能演完”。
- 衔接检查上一段末态与下一段起态；抬眼/低头可并存，凝视/四处扫视不能在同一时刻同时成立。冲突依据具体语义判断，不建立越来越长的禁词表。
- 末态允许持续抽泣、持续笑、疑惑加深或受控静止。只在需求或选定表演需要时才收束。

镜头和表演节拍分别计时：一个镜头可以有多个节拍。使用 clip 绝对秒数；独立测试连续覆盖指定时长，完整生产只记录实际表演区间。多人同步写在同一节拍正文，避免用重叠节拍伪装剪切。摄影不是演员表演通道。

## C → D 保留契约

S4 写入剧本页“有序表演块”；S5 引用并承接同一正文，检查构图能看见必要部位，不能为了换景别打断高光。S6 只加已有镜头/素材上下文，不把细节总结为情绪名称。

每个表演块保留：角色、时间、正文、关联条目、关键细节与保留理由、有意调整。元数据不进模型 Prompt。正常对话中保留这些核对信息即可，不强制用户维护 JSON。

需要落盘或自动核对时，用 `templates/performance-record.json` 的可选 sidecar（见 `references/performance-record.md`）；它保存获准的 C 层正文，脚本核对 D 层逐节拍一致性。不要从最终 Prompt 倒填记录再宣称“上游保真已通过”。有意修订必须先更新上游表演块及修改记录。

## 交付与审阅

直接测试默认交付：一句模式/目标说明 + 可复制 Prompt + 简短取材/改动说明 + 检查状态。不附网站地址或条目来源信息；需要区分的是原文与改编，不是出处。原文模式仅给原文正文，编排说明放外面。

审阅四层分开：格式、保真、表演质量、成片。原文可逐字自动比较；改编关系、语义矛盾和表演充分性由审阅者检查。没有成片只能写“未验证”，文本获用户认可不等于视频效果可靠。

表演审阅回答：识别性细节是否仍在？控制有无可见证据？顺序/同步/末态是否正确？时间能否容纳高光？镜头能否看到？是否为了新颖加了不相关动作？只输出实际问题，不逐项复述空泛打勾表。
