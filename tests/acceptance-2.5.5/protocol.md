# 2.5.5 验收协议

版本定位：故事开发与编剧工作流升级，不是 Prompt 引擎升级。基线 `v2.5.0`（`47067bd`）。全程不使用子代理，不使用网络抓取；方法来源的原页本次未访问，均标 `[第三方转述]`。

## 目标能力（可观察）

1. 给一个普通题目，能发展出具体人物与值得观看的故事，而不只是漂亮设定。
2. 多个候选在人、事件和关系上真正不同，而非只换职业、地点、道具。
3. 能把想法写成完整场景和连续故事，台词不只是替作者解释主题。
4. 收到批评后，能修到问题所在，同时保留原来的优点。

保护区：原始情绪库、强度与克制机制、表演细节保真、核心 Prompt 编译及生产约束不调整；已有作品不因新规则被强制重写。保护区文件清单与 v2.5.0 哈希在 `tests/test_acceptance_255.py`。

## 架构

```
需求／已有材料 → 判断意图、材料成熟度、锁定项（S2）
→ 故事开发：构思 ↔ 人物与关系 ↔ 关键场景试写 ↔ 事件组织（S3a / S3b / S3c 是成果类型，不是必经关卡）
→ 完整故事／剧本 → 有针对性地修订（修订账本，达到目标就停）
→ 现有表演、分镜与 Prompt 生产链（不变）
```

"明确任务使用稳定流程，开放创作保留判断空间"是本次架构选择，不引入多代理或框架。工程依据：Anthropic《Building effective agents》（2024-12，https://www.anthropic.com/engineering/building-effective-agents，本次未重新访问）主张按任务选择最简单够用的工作流，而不是增加复杂度 `[第三方]`。

## 三层验收

| 层级 | 验什么 | 能证明什么 | 本次状态 |
|---|---|---|---|
| 工程回归 | 路由不随措辞漂移、概念校验修复、授权边界（自主 / 确认 / 保存分离）、保护区无差异、旧能力测试全过 | 修复正确、没有已知回归 | **已执行**，见 `engineering-report.md` |
| 完整创作任务 | 宽泛题目 → 故事 → 剧本 → 改写；覆盖普通题材、无强对抗、强对白、无对白、喜剧、群像、30 秒与多场景 | 工作流能实际完成创作 | **未开始**（用户指示先到工程验收）；题目清单在 `cases.md` |
| 旧新版非盲对照 | 同题、同模型、相近预算，比较 2.5.0 / 只做 P0 / 完整 2.5.5，保留全部结果 | 提供改善迹象，不能证明独立显著提升 | **未开始**；方法在 `compare.md` |

## 两个必须分开的结论

- **版本开发完成**：规则冲突修复、工作流跑通、保护区无回归 → 由工程回归层判断。
- **创作能力提升**：完整作品出现可指出的改善，并报告失败、持平和退步案例 → 由后两层判断。只有自评或少数优秀样例时，只能称"非盲测试呈现改善"，不能宣布"显著增强"。

## 完整创作任务的验收方式（待执行）

- 先不看分析说明，只读故事正文：能否理解人物、感受到进展，并指出哪些具体段落有吸引力。
- 候选：把职业、地点、道具互换后，故事是否仍然是不同的故事。
- 对白：改写后既符合人物处境，也保留戏剧吸引力；不是越碎、越绕、越短就越好。
- 修订：修到问题所在，同时保留上一版的优点；有修订账本。
- 每个任务保留输入、初稿、修订、得失与未解决项；不计算胜率。
