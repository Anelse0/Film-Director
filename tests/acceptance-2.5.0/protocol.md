# 2.5.0 验收协议与开发追踪

## 任务与边界

用户批准 P0–P3 开发并推送 GitHub。随后明确“全程不用，明确标注非盲验证”，取代原计划中需要隔离生成/评审上下文的盲测。此次全程由主代理完成，不调用子代理，不调用视频生成 API，不改用户偏好账本，不把模型判断写成用户偏好。

基线：`v2.4.0`，commit `1a460b344f9309e12acbe7659c8f11018f5ab50e`。独立开发工作树，基线文件和旧完整评测档案不修改。开发前 `bash tests/run_tests.sh`：42 项 shell 检查、78 项 unittest 通过；真实媒体测试执行。

## 实施对应

| 优先级 | 机制与交付 | 检查方式 |
|---|---|---|
| P0 | 在入口、S3b/c、S4/5、因果文档及模板中解除逐句预排、固定回避、策略→身体映射、强制物件 | 扫描调用链、逐文件审阅；保留历史 CHANGELOG 与原 30 秒内容 |
| P1 | 共用交流处境、声音三层、连续片段诊断；观察材料与诊断反例按需读取 | 核对出处与材料类型；新案例不搬样例答案 |
| P2 | C 层自身有效性、道具/视点连续性、三时间轨、S6 保真；退役 W19，修有限表面提示 | 自动回归、原库与旧 30 秒字节保护、正式生产预检 |
| P3 | 16 个新片段（8 类各 2）、6 类回归护栏、一条完整生产 Demo、明确局部修订得失 | 主代理非盲文本审阅；不计算胜率，不声称因果证明 |

## 非盲验证方法

主代理已知旧结果、诊断和实现；创作、审阅在同一上下文。新题不等于独立留出集。每个新题保留具体输入、完整短片段与局部判断；若有实质修订保留初稿。每题一次初稿，必要修改单独记录。不重新模拟“旧版生成”，不使用 `blind_eval.py` 包装成盲测。旧 2.4.0 强对白片段只作失败诊断参考，不能与当前新题计算版本质量差。

新题覆盖：强交锋、平静高利害、双方激动、长表达、直接交流、合理回避/误解、同人不同对象、有意风格/喜剧。样例是虚构场景，不依赖未核实行业制度。6 类护栏：无对白/合作、持续情绪与原库、30 秒原设计、定点改稿、锁定内容与事实边界、道具视点及生产闭环。

准入：自动检查没有新增未处理失败；原库与原 30 秒不损伤；生产 Demo 能通过严格文本/记录预检；已发现的具体缺陷要修订或明确保留风险。艺术判断只报告证据、损失与不确定性。演员朗读、独立盲选、用户偏好验证、成片验证均未执行，不能据此次验收宣称总体编剧能力已被实验验证提升。
